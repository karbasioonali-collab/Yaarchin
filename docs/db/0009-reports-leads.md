# Migration 0009 — امتیاز جدیت مشتری (گزارش‌ها)

- **وضعیت:** ✅ تأیید شد (2026-10-07).
  - روی Postgres محلی سندباکس اجرا و تست شد، هم قبل و هم بعد از migrate.
  - **روی لیارا هنوز اجرا نشده.** مالک بعد از استقرار کد اجرا می‌کند.
- **فایل SQL:** `web/drizzle/0009_reports_leads.sql`
- **نوع تغییر:** فقط افزودنی: **۲ جدول تازه**. به هیچ جدول، ستون یا داده‌ی موجودی دست نمی‌زند. ایندکس تازه روی جدول‌های قبلی لازم نشد.
- **تعریف در کد:** `web/src/db/schema/leads.ts`. توضیح کامل: `docs/infoyaarchin.md` بخش ۲۸.

| جدول | چیست |
|---|---|
| `lead_score_rules` | قانون‌های امتیاز جدیت: کلید یکتا، نوع (منبع داده)، اسم، امتیاز هر واحد، سقف، «فقط N روز اخیر»، روشن/خاموش، params (مثلاً کلید نشانه)، ترتیب، منبع (system/admin/ai، CHECK)، آخرین ویرایشگر. CHECK: امتیاز و سقف منفی نیستند، روزها ۱ تا ۳۶۵۰ |
| `customer_signals` | جای «نشانه»های هر مشتری که AI بعداً می‌نویسد (مثل تعداد سفارش)؛ کلید اصلی (کاربر، کلید). فعلاً خالی |

- عمداً **CHECK روی `kind` نیست**: نوع تازه‌ی قانون فقط کد می‌خواهد، نه migration.
- **کلیدهای خارجی:** `customer_signals.user_id` با حذف کاربر پاک می‌شود؛ `lead_score_rules.updated_by` SET NULL.
- **Seed** (داده، نه ساختار):
  - دسترسی‌های `reports.view` و `reports.staff`؛
  - ۶ قانون پیش‌فرض (فقط اگر نباشند)؛
  - اسم تازه‌ی سوئیچ `features.reports`: «بخش «گزارش‌ها» در پنل».
- **قبل از migrate** هیچ صفحه‌ای خطا نمی‌دهد (`reportsReady()`): گزارش بدون بخش امتیاز کار می‌کند.

## اجرا روی لیارا (به همین ترتیب)
1. بک‌آپ دیتابیس `yaarchin-db`.
2. Merge و صبر تا «Deploy to Liara» سبز شود.
3. در کنسول برنامه:
   - `npm run db:migrate`
   - `npm run db:seed`
4. اگر `auth.enforce_permissions` روشن است، `reports.view` (و برای مدیرها `reports.staff`) را در «نقش‌ها و دسترسی» بدهید.
