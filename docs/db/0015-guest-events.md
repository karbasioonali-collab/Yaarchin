# Migration 0015: ایندکس رویدادهای مهمان (بخش ۴۸ در docs/infoyaarchin.md)

فقط یک ایندکس؛ بدون ستون یا جدول تازه (ستون `events.anon_id` از migration اول هست).

```sql
CREATE INDEX "events_anon_idx" ON "events" USING btree ("anon_id","occurred_at") WHERE "events"."anon_id" is not null;
```

- **چرا:** این کارها با شناسه‌ی مهمان (کوکی `yid`) کار می‌کنند:
  - پیدا کردن «ورود به سایت»ِ امروز و بازدید تکراریِ ۳۰ دقیقه‌ی اخیر؛
  - سقف ۲۰۰ رویداد در روز؛
  - وصل شدن بازدیدها به حساب بعد از ورود؛
  - پاک کردن بازدیدهای مهمانِ مرورگری که کارمند در آن وارد شد.
  - بدون ایندکس، با بزرگ شدن جدول events همه‌ی این‌ها کل جدول را می‌گردند.
- **قبل از migrate:** کد بدون این ایندکس هم درست کار می‌کند، فقط کندتر. تست `tests/e2e/guest-pre.e2e.mjs` همین را روی دیتابیسِ تا ۰۰۱۴ می‌سنجد.
- **ایندکس جزئی** (`where anon_id is not null`): رویدادهای مشتری (anon_id خالی) در آن نیستند، پس کوچک می‌ماند.
- **برگشت:** `DROP INDEX "events_anon_idx";` (داده‌ای از دست نمی‌رود).
