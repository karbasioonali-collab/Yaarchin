# Migration 0007 — پیگیری کارخانه‌ها و صف پیامک

- **وضعیت:** ✅ تأیید شد (2026-10-05).
  - روی Postgres محلی سندباکس اجرا و تست شد، هم قبل و هم بعد از migrate.
  - **روی لیارا هنوز اجرا نشده.** مالک بعد از استقرار کد اجرا می‌کند.
- **فایل SQL:** `web/drizzle/0007_followup_sms.sql`
- **نوع تغییر:** فقط افزودنی: ۵ جدول تازه با ایندکس‌ها و کلیدهای خارجی‌شان (`ALTER TABLE` فقط برای افزودن کلید خارجی به همین جدول‌های تازه است). به هیچ جدول، ستون یا داده‌ی موجودی دست نمی‌زند.
- **تعریف در کد:** `web/src/db/schema/followup.ts`. توضیح کامل: `docs/infoyaarchin.md` بخش ۲۵.

| جدول | چیست |
|---|---|
| `inquiries` | درخواست مشتری از داخل یک گفتگو: محصول یا اسم محصول (CHECK: یکی لازم است)، تعداد (CHECK: بزرگ‌تر از صفر)، توضیح، وضعیت open/done/cancelled (CHECK)، سازنده |
| `inquiry_suppliers` | کارخانه‌های هر درخواست با وضعیت فعلی pending/contacted/replied/quoted/declined (CHECK)، آخرین یادداشت، لیستینگ. یکتا: درخواست × کارخانه |
| `inquiry_supplier_events` | تاریخچه‌ی فقط افزودنی تغییر وضعیت‌ها با یادداشت، ثبت‌کننده و لینک به ردیف `company_correspondence` |
| `sms_outbox` | هر پیامک واقعی یا آزمایشی: گیرنده، نوع، متن (کد ورود پوشانده)، وضعیت test/sent/failed/skipped (CHECK)، سرویس‌دهنده، خطا، گفتگو |
| `staff_notification_prefs` | روشن/خاموش پیامک هشدار هر کارمند |

- **کلیدهای خارجی:**
  - گفتگو، درخواست، کارخانه و ردیف پیگیری RESTRICT: تاریخچه‌ی پیگیری پاک نمی‌شود. (`db:seed-demo -- --remove` ردیف‌های پیگیری کارخانه‌های نمونه را خودش اول پاک می‌کند.)
  - محصول، لیستینگ، ردیف مکاتبه و کاربر سازنده SET NULL. اسم محصول همیشه در `product_title` هم ذخیره می‌شود.
  - `sms_outbox`: کاربر و گفتگو SET NULL. `staff_notification_prefs` با حذف کاربر پاک می‌شود.
- **Seed** (داده، نه ساختار): گروه تنظیم `sms`:
  - `sms.chat_cooldown_minutes` = ۳۰
  - `sms.reminder_minutes` = ۱۵
  - `sms.work_start` = 09:00، `sms.work_end` = 18:00
  - `sms.work_days` = شنبه تا چهارشنبه (`[6,0,1,2,3,4]`)
- **دسترسی تازه:** ندارد؛ از `chats.*` و `companies.view` موجود استفاده می‌کند.
- **قبل از migrate** سایت و پنل خطا نمی‌دهند (`followupReady()`): چت مثل قبل کار می‌کند، هشدار پیامکی رد می‌شود و صفحه‌های تازه پیام «اول migrate» می‌دهند.

## اجرا روی لیارا (به همین ترتیب)
1. بک‌آپ دیتابیس `yaarchin-db`.
2. Merge و صبر تا «Deploy to Liara» سبز شود.
3. در کنسول برنامه:
   - `npm run db:migrate`
   - `npm run db:seed`
4. شماره‌ی موبایل کارمندانی که باید پیامک بگیرند در حسابشان ثبت باشد.
