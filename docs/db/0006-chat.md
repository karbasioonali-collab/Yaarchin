# Migration 0006 — چت مشتری با کارشناس

- **وضعیت:** ✅ تأیید شد (2026-10-05).
  - روی Postgres محلی سندباکس اجرا و تست شد، هم قبل و هم بعد از migrate.
  - **روی لیارا هنوز اجرا نشده.** مالک بعد از استقرار کد اجرا می‌کند.
- **فایل SQL:** `web/drizzle/0006_chat.sql`
- **نوع تغییر:** فقط افزودنی: ۴ جدول تازه. به هیچ جدول، ستون یا داده‌ی موجودی دست نمی‌زند.
- **تعریف در کد:** `web/src/db/schema/chat.ts`. توضیح کامل: `docs/infoyaarchin.md` بخش ۲۴.

| جدول | چیست |
|---|---|
| `conversations` | گفتگو: مشتری، نوع (product/general، CHECK)، محصول، موضوع، وضعیت (open/closed، CHECK)، کارشناس، زمان‌ها، `attention` و `attention_reason` (مرحله‌ی AI). یکتا: یک گفتگوی محصولی برای هر مشتری × محصول |
| `chat_messages` | پیام‌ها و رویدادها، فقط افزودنی. فرستنده: customer/staff/system/ai (CHECK). `visible_to_customer`، `meta` (JSON). متن ۱ تا ۴۰۰۰ نویسه (CHECK) |
| `conversation_reads` | آخرین پیام خوانده‌شده‌ی هر کاربر در هر گفتگو |
| `conversation_flags` | برچسب «نیاز به بررسی / نیاز به کارشناس» با دلیل و حل‌شدن (برای مرحله‌ی AI) |

- **کلیدهای خارجی:**
  - مشتری و گفتگو RESTRICT: گفتگو یا پیام پاک نمی‌شود.
  - محصول SET NULL: با حذف محصول، گفتگو می‌ماند.
  - کارشناس و فرستنده SET NULL.
  - `conversation_reads` با حذف کاربر یا گفتگو پاک می‌شود.
- **Seed** (داده، نه ساختار):
  - دسترسی‌های `chats.view_all`، `chats.reply`، `chats.assign`؛
  - تنظیم `chat.auto_reply` با متن پیش‌فرض «سلام، پیامتان رسید. کارشناس یارچین به‌زودی پاسخ می‌دهد.»
- **قبل از migrate** سایت و پنل خطا نمی‌دهند (`chatReady()`): باکس و دکمه‌ی چت، تب «گفتگوهای من» و منوی «گفتگوها» پنهان‌اند یا پیام «اول migrate» می‌دهند.

## اجرا روی لیارا (به همین ترتیب)
1. بک‌آپ دیتابیس `yaarchin-db`.
2. Merge و صبر تا «Deploy to Liara» سبز شود.
3. در کنسول برنامه:
   - `npm run db:migrate`
   - `npm run db:seed`
4. اگر `auth.enforce_permissions` روشن است، دسترسی‌های گفتگو را در «نقش‌ها و دسترسی» به نقش کارشناس بدهید (معمولاً `chats.reply`).
