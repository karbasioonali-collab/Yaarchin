# Migration 0010 — دستیار هوشمند یارچین (AI در چت)

- **وضعیت:** ✅ تأیید شد (2026-10-26).
  - روی Postgres محلی سندباکس تست شد: قبل از migrate (دیتابیس ۰۰۰۹)، بعد از migrate، و ارتقای ۰۰۰۹ ← ۰۰۱۰ با seed.
  - **روی لیارا هنوز اجرا نشده.** مالک بعد از استقرار کد اجرا می‌کند.
- **فایل SQL:** `web/drizzle/0010_ai.sql`
- **نوع تغییر:** فقط افزودنی: **۵ جدول تازه**. به هیچ جدول یا ستون موجودی دست نمی‌زند.
  - وضعیت دستیار در هر گفتگو عمداً جدول جداست، نه ستون تازه روی `conversations`.
- **تعریف در کد:** `web/src/db/schema/ai.ts`. توضیح کامل: `docs/infoyaarchin.md` بخش ۲۹.

| جدول | چیست |
|---|---|
| `ai_conversation_state` | یک ردیف برای هر گفتگویی که دستیار در آن فعال بوده. ستون‌ها: `mode` (ai/human، CHECK)، تعداد جواب‌ها، «در حال نوشتن از»، زمان، دلیل و کاربرِ ساکت کردن |
| `ai_requests` | لاگ هر درخواست به مدل یا هر تصمیم بدون مدل. ستون‌ها: کاربرد (chat / connection_test)، حالت (live/test، CHECK)، گفتگو، پیام، جواب، مدل، مدل پشتیبان، وضعیت، نتیجه، توکن‌ها، هزینه به تومان، زمان پاسخ، خطا، meta |
| `ai_feedback` | 👍/👎 مشتری و «جواب اشتباه» کارشناس روی پیام‌های دستیار. یکتا روی (پیام، کاربر، منبع) |
| `kb_items` | پایگاه دانش: سؤال، جواب، شکل‌های دیگر پرسیدن، دسته، وضعیت (active/draft، CHECK)، آخرین بررسی و بررسی‌کننده |
| `kb_item_versions` | تاریخچه‌ی هر ذخیره‌ی پایگاه دانش (نسخه‌ی کامل و ویرایشگر) |

- **کلیدهای خارجی:**
  - با حذف گفتگو یا پیام پاک می‌شوند: وضعیت، بازخورد، نسخه‌ها.
  - `ai_requests` لاگ است و با حذف گفتگو یا پیام فقط ارجاعش NULL می‌شود.
  - ستون‌های کاربر SET NULL؛ `ai_feedback.user_id` CASCADE.
- **ایندکس‌ها:**
  - `ai_requests (created_at)` برای مصرف روزانه؛
  - `(conversation_id, created_at)`؛
  - `kb_items (status, last_reviewed_at)`؛
  - `ai_conversation_state (mode)`.
- **Seed** (داده، نه ساختار):
  - دسترسی‌های `ai.settings` و `ai.knowledge`.
  - ۹ تنظیم گروه `ai` (سقف‌ها و لیست سیاه).
  - حذف تنظیم‌های قدیمی `ai.task.*`.
  - سوئیچ `features.ai_agent` **یک بار** خاموش می‌شود: فقط اگر روشن باشد و هیچ ادمینی دستی عوضش نکرده باشد (`updated_by` خالی).
    - روی لیارا از پیش‌فرض قدیمی روشن بود؛ بدون این کار، با وارد کردن کلید، دستیار برای مشتری‌ها روشن می‌شد.
  - ۴۰ پیش‌نویس پایگاه دانش از `web/src/db/kb-drafts.json` (با وضعیت `draft`). فقط وقتی پایگاه دانش خالی است وارد می‌شوند.
- **قبل از migrate** هیچ صفحه‌ای خطا نمی‌دهد (`aiReady()`):
  - چت مثل قبل کار می‌کند و دستیار کاملاً خاموش است.
  - صفحه‌های دستیار پیام «بعد از migration ۰۰۱۰» می‌دهند.
  - تست: `web/tests/e2e/ai-pre.e2e.mjs`.

## اجرا روی لیارا (به همین ترتیب)
1. بک‌آپ دستی دیتابیس `yaarchin-db` در پنل لیارا.
2. Merge و صبر تا «Deploy to Liara» سبز شود.
3. در کنسول برنامه:
   - `npm run db:migrate`
   - `npm run db:seed`
4. ادامه (کلید و «تست اتصال»): `docs/liara-setup.md` بخش ۲۰.
