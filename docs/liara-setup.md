# راه‌اندازی روی لیارا

> هیچ connection string، رمز یا توکنی را در ریپو یا چت قرار ندهید. جای هر راز: متغیرهای محیطی برنامه در پنل لیارا، یا Secrets ریپو در گیت‌هاب.

## وضعیت فعلی
| مورد | وضعیت |
|---|---|
| دیتابیس `yaarchin-db` | ✅ ساخته شده: PostgreSQL 18.4، پلن زمین، شبکه‌ی `yaarchin-net`، افزونه‌ی pgvector فعال |
| برنامه‌ی سایت `yaarchin` | ✅ مستقر شده: https://yaarchin.liara.run |
| استقرار خودکار از گیت‌هاب | ✅ فعال (push روی main یا اجرای دستی) |
| جدول‌ها و اولین ادمین | ✅ migration ۰۰۰۰، seed و create-admin |
| سایت عمومی (فاز ۴، migration ۰۰۰۱) | ✅ مستقر شده (بخش ۷) |
| امتیاز «جذاب برای واردات» (migration ۰۰۰۲) | ✅ مستقر شده (بخش ۸) |
| مشتری، علاقه‌مندی و ثبت رفتار (migration ۰۰۰۳) | ⏳ بعد از Merge: بخش ۱۱ |
| پنل دسته‌ها، کارخانه‌ها و محصولات (migration ۰۰۰۴) | ⏳ بعد از Merge: بخش ۱۲ |
| پاک کردن داده‌ی demo | ⚠️ **قبل از افتتاح سایت یا ورود داده‌ی واقعی:** `npm run db:seed-demo -- --remove` در کنسول |

> اگر هنگام استقرار یا در کنسول خطایی دیدید، اول بخش ۱۲ فایل `docs/infoyaarchin.md` («درس‌های استقرار روی لیارا») را ببینید.

---

## ۱. دیتابیس (انجام شده)
- **نسخه‌ی Postgres:** کد با نسخه‌ی ۱۳ به بالا کار می‌کند.
- **pgvector:** روی لیارا **ایندکس HNSW پشتیبانی نمی‌شود**؛ در مرحله‌ی چت از IVFFlat استفاده می‌کنیم.
- **بررسی pgvector:** در کنسول برنامه این دستور را بزنید؛ اگر یک ردیف برگرداند، pgvector در دسترس است:
  `select name, default_version from pg_available_extensions where name = 'vector';`

## ۲. ساخت برنامه‌ی سایت (NextJS)
1. در پنل لیارا به **برنامه‌ها** بروید و **ایجاد برنامه** را بزنید.
2. **پلتفرم:** **NextJS**.
3. **شناسه:** `yaarchin`
   - این اسم در `web/liara.json` نوشته شده.
   - اگر آزاد نبود، هر شناسه‌ی دیگری انتخاب کنید و در `web/liara.json` مقدار `"app"` را همان بگذارید.
4. **شبکه‌ی خصوصی:** `yaarchin-net`؛ همان شبکه‌ی دیتابیس. ⚠️ **شبکه‌ی خصوصی بعد از ساخت برنامه قابل تغییر نیست.**
5. **منطقه:** همان منطقه‌ای که دیتابیس در آن است (ایران).
6. **پلن:** کوچک‌ترین پلن کافی است.
   - build پروژه‌ی Next.js حافظه می‌خواهد. اگر build با خطای کمبود حافظه تمام شد، یک پله پلن را بالا ببرید.
7. **ایجاد برنامه** را بزنید. برنامه فعلاً خالی است و این طبیعی است.

## ۳. متغیرهای محیطی
در صفحه‌ی برنامه‌ی `yaarchin` به **تنظیمات ← متغیرها** بروید و این را اضافه کنید:

| نام | مقدار |
|---|---|
| `DATABASE_URL` | از صفحه‌ی دیتابیس `yaarchin-db`، بخش **اطلاعات اتصال**، **URI شبکه‌ی خصوصی** را کپی کنید |

- **`APP_ENCRYPTION_KEY` دیگر لازم نیست** (از 2026-09-24، با حذف ورود دومرحله‌ای).
  - اگر قبلاً ثبتش کرده‌اید، ماندنش ضرری ندارد؛ کد دیگر از آن استفاده نمی‌کند.
  - با این حال یک نسخه‌اش را نگه دارید، برای روزی که ورود دومرحله‌ای برگردد.

## ۴. اتصال گیت‌هاب به لیارا (استقرار خودکار، بدون کامپیوتر)
1. **ساخت توکن:** در پنل لیارا به **حساب کاربری ← کلید API** بروید و یک کلید بسازید و کپی کنید.
2. **ثبت توکن در گیت‌هاب:** در ریپو به **Settings ← Secrets and variables ← Actions ← New repository secret** بروید:
   - Name: `LIARA_API_TOKEN`
   - Secret: کلید API لیارا
3. **رساندن فایل‌ها به main:** فایل‌های استقرار باید در برنچ `main` باشند؛ یعنی Pull Request برنچ کار را merge کنید.
4. **اجرای استقرار:** بعد از هر push روی `main` که پوشه‌ی `web/` را تغییر دهد، استقرار خودکار انجام می‌شود.
   - اجرای دستی هم ممکن است: **Actions ← Deploy to Liara ← Run workflow**.
   - قبل از استقرار، بررسی تایپ و lint اجرا می‌شود. اگر خطا باشد، چیزی روی سایت نمی‌رود.

## ۵. اولین اجرا (یک‌بار، از کنسول برنامه روی لیارا)
بعد از اولین استقرار موفق، در صفحه‌ی برنامه به **کنسول** بروید:
```
npm run db:migrate      # ساخت جدول‌ها (migration 0000 تأییدشده)
npm run db:seed         # نقش‌ها، دسترسی‌ها، سوئیچ‌ها
npm run create-admin    # نام، موبایل، ایمیل و رمز اولین ادمین را می‌پرسد (موبایل یا ایمیل، حداقل یکی)
```
- پیغام `.env not found. Continuing without it.` طبیعی است؛ مقدارها از متغیرهای محیطی پنل خوانده می‌شوند.
- بعد به `https://<دامنه‌ی برنامه>/admin` بروید و وارد شوید.
- ورود فقط با موبایل (یا ایمیل) و رمز است؛ ورود دومرحله‌ای ندارد.
- ادمین بعداً با **موبایل یا ایمیل** (هر کدام که ثبت کرده) وارد می‌شود. در `create-admin` هر کدام را نمی‌خواهید، خالی بگذارید و Enter بزنید.
- **قانون رمز:** حداقل ۱۲ کاراکتر، شامل حرف بزرگ و کوچک انگلیسی، عدد و نماد. `create-admin` رمز ضعیف را قبول نمی‌کند.
- **بررسی سلامت:** آدرس `https://<دامنه>/api/v1/health` باید `{"ok":true,"db":"up"}` برگرداند.

## ۶. migrationهای بعدی
1. هر migration جدید قبل از اجرا با توضیح در `docs/db/` پیشنهاد می‌شود.
2. بعد از **تأیید** مالک، اول از بخش **بک‌آپ** دیتابیس در لیارا یک بک‌آپ گرفته می‌شود.
3. بعد در کنسول برنامه `npm run db:migrate` اجرا می‌شود.

## ۷. استقرار سایت عمومی (فاز ۴، migration ۰۰۰۱) — به همین ترتیب
1. **بک‌آپ:** در پنل لیارا ← دیتابیس `yaarchin-db` ← بخش **بک‌آپ** ← ساخت بک‌آپ.
2. **Merge** و صبر تا اجرای «Deploy to Liara» در تب Actions گیت‌هاب سبز شود (حدود ۳ دقیقه).
   - از این لحظه تا قدم ۳، سایت بدون محصول و با محتوای پیش‌فرض باز می‌شود و خطا نمی‌دهد.
3. **کنسول برنامه‌ی `yaarchin`:**
   ```
   npm run db:migrate      # ساخت ۱۰ جدول تازه (migration 0001)
   npm run db:seed         # دو دسترسی تازه: site.manage و contact.view
   npm run db:seed-demo    # داده‌ی نمونه: ۱۱ دسته، ۱۰ محصول، عکس‌های موقت
   ```
   پیام موفقیت هر کدام: «migrationها اعمال شدند.»، «seed انجام شد.»، «داده‌ی demo ساخته شد: …».
4. **بررسی:** صفحه‌ی اصلی، یک محصول (مثلاً `/p/portable-blender`)، `/api/v1/health`، و در پنل «محتوای سایت» و «پیام‌های تماس».
5. **بعداً، قبل از ورود داده‌ی واقعی:** `npm run db:seed-demo -- --remove`.

- **چرا migrate بعد از استقرار؟** فایل migration همراه کد جدید می‌رسد و کنسول لیارا همیشه همان کد در حال اجرا را دارد. کد جدید طوری نوشته شده که تا اجرای migrate خطا ندهد (`docs/infoyaarchin.md` بخش ۱۵).

## ۸. امتیاز «جذاب برای واردات» (migration ۰۰۰۲) — به همین ترتیب
1. **بک‌آپ** دیتابیس `yaarchin-db`.
2. **Merge** و صبر تا «Deploy to Liara» سبز شود. تا قدم ۳ سایت بدون ستاره و بدون خطا کار می‌کند.
3. **کنسول برنامه‌ی `yaarchin`:**
   ```
   npm run db:migrate      # ستون import_score (migration 0002)
   npm run db:seed         # دسترسی تازه: products.rate
   npm run db:seed-demo    # (اختیاری) امتیاز‌های نمونه روی داده‌ی demo
   ```
4. **بررسی:** پنل ← «محصولات»، و یک صفحه‌ی محصول مثل `/p/portable-blender` (۴٫۵ ستاره).
- اگر `db:seed-demo` داده‌ی demo را از نو بسازد، امتیازهایی که روی محصولات demo دستی ثبت کرده‌اید به مقدار نمونه برمی‌گردد.

## ۹. اگر رمز ادمین گم شد
دستور جدا لازم نیست. همان `create-admin` رمز کاربرِ موجود را عوض می‌کند.
1. پنل لیارا ← برنامه‌ی `yaarchin` ← **کنسول**.
2. اجرا کنید:
   ```
   npm run create-admin
   ```
3. به سؤال‌ها جواب دهید:
   - **نام:** نام درست خودتان را بنویسید. نام قبلی با همین بازنویسی می‌شود.
   - **موبایل و ایمیل:** دقیقاً همانی که حساب با آن ساخته شده. حداقل یکی لازم است. از روی همین، کاربرِ موجود پیدا می‌شود؛ اگر اشتباه بنویسید، ادمین تازه‌ای ساخته می‌شود.
   - **رمز تازه:** موقع تایپ دیده نمی‌شود (یک بار پرسیده می‌شود؛ با دقت تایپ کنید). حداقل ۱۲ کاراکتر، با حرف بزرگ و کوچک انگلیسی، عدد و نماد.
4. نتیجه:
   - رمز عوض می‌شود؛
   - حساب فعال می‌شود، حتی اگر غیرفعال شده بود؛
   - نقش ادمین دوباره داده می‌شود.
5. **نشست‌های باز قبلی بسته نمی‌شوند.** اگر نگرانید کس دیگری وارد حسابتان شده باشد، بعد از ورود در پنل ← «کاربران» ← حساب خودتان ← «بستن همه‌ی نشست‌ها».
- رمز را هیچ‌وقت در چت، فایل یا اسکرین‌شات نفرستید.

## ۱۰. روشن کردن امن سوئیچ «اعمال واقعی دسترسی نقش‌ها» (`auth.enforce_permissions`)
- **خاموش (الان):** هر کاربر پنل به همه‌ی بخش‌ها دسترسی دارد.
- **روشن:** هر کارشناس فقط به دسترسی‌هایی که به نقشش داده شده دسترسی دارد.
- ادمین همیشه به همه‌چیز دسترسی دارد، پس با روشن کردن سوئیچ قفل نمی‌شود.
- فقط ادمین می‌تواند سوئیچ، نقش‌ها و نقش ادمین را تغییر دهد.

قدم‌ها:
1. پنل ← «کاربران»: مطمئن شوید حساب خودتان نقش **ادمین** دارد و **فعال** است. بهتر است یک ادمین دوم هم داشته باشید، مثلاً حساب پشتیبان خودتان با ایمیل دیگر.
2. پنل ← «نقش‌ها و دسترسی» ← «کارشناس»: تیک دسترسی‌هایی را بزنید که کارشناس‌ها لازم دارند (مثلاً پیام‌های تماس، امتیاز محصولات) و ذخیره کنید.
3. پنل ← «تنظیمات و سوئیچ‌ها» ← «اعمال واقعی دسترسی نقش‌ها» را روشن کنید.
4. در یک پنجره‌ی ناشناس (Incognito) با یک حساب کارشناس وارد شوید و ببینید فقط بخش‌های مجاز در منو هست.
5. اگر چیزی کم بود، به نقش اضافه کنید. سوئیچ را برای این کار خاموش نکنید.
6. **اگر خودتان به هر دلیلی نتوانستید وارد شوید:** بخش ۹ (رمز یا نقش ادمین را از کنسول برمی‌گرداند).

## ۱۱. ثبت‌نام و ورود مشتری، علاقه‌مندی (migration ۰۰۰۳) — به همین ترتیب
1. **بک‌آپ:** در پنل لیارا ← دیتابیس `yaarchin-db` ← بخش **بک‌آپ** ← ساخت بک‌آپ.
2. **Merge** و صبر تا «Deploy to Liara» در تب Actions گیت‌هاب سبز شود.
   - تا قدم ۳ سایت بدون خطا کار می‌کند.
   - ثبت‌نام و ورود مشتری کار می‌کند؛ قلب و پروفایل کسب‌وکار «به‌زودی» می‌گویند.
3. **کنسول برنامه‌ی `yaarchin`:**
   ```
   npm run db:migrate      # ۴ جدول تازه (migration 0003)
   npm run db:seed         # دسترسی‌های customers.view و customers.manage، تنظیم auth.customer_session_days
   ```
   پیام موفقیت: «migrationها اعمال شدند.» و «seed انجام شد.»
4. **بررسی:**
   - در پنجره‌ی ناشناس، `/login` ← ثبت‌نام با یک موبایل یا ایمیل آزمایشی ← روی یک محصول قلب بزنید ← `/favorites`.
   - در پنل ← «مشتریان» ← همان مشتری: علاقه‌مندی و بازدیدها دیده شود.
   - مشتری آزمایشی را همان‌جا غیرفعال کنید.
- **سوئیچ «ثبت‌نام مشتری»** (`features.customer_signup`) از این نسخه واقعاً کار می‌کند و الان **روشن** است. اگر هنوز نمی‌خواهید کسی ثبت‌نام کند، قبل از Merge یا بلافاصله بعدش خاموشش کنید. ورود مشتری‌های قبلی همیشه باز است.
- **ورود با کد پیامکی** ساخته شده ولی تا سرویس‌دهنده‌ی پیامک وصل نشود، دیده نمی‌شود (`docs/infoyaarchin.md` بخش ۱۸).

## ۱۲. پنل دسته‌ها، کارخانه‌ها و محصولات (migration ۰۰۰۴) — به همین ترتیب
1. **بک‌آپ:** پنل لیارا ← دیتابیس `yaarchin-db` ← بخش **بک‌آپ** ← ساخت بک‌آپ.
2. **Merge** و صبر تا «Deploy to Liara» سبز شود.
   - تا قدم ۳ سایت و پنل بدون خطا کار می‌کنند.
   - ساخت کارخانه، تماس، مکاتبه، زمان آماده‌سازی، و وزن و کارتن پیام «بعد از migration ۰۰۰۴» می‌دهند.
3. **کنسول برنامه‌ی `yaarchin`:**
   ```
   npm run db:migrate      # ۳ جدول و ۷ ستون تازه (migration 0004)
   npm run db:seed         # ۵ دسترسی تازه (دسته‌ها، کارخانه‌ها، محصولات، مکاتبه)
   npm run db:seed-demo    # (اختیاری) تماس، مکاتبه و زمان آماده‌سازی نمونه روی داده‌ی demo
   ```
4. **بررسی:** در پنل، منوهای «دسته‌بندی‌ها»، «کارخانه‌ها» و «محصولات»، و یک محصول نمونه ← «قیمت و جزئیات» یک کارخانه.
- `db:seed-demo` داده‌ی demo را از نو می‌سازد: هر چیزی که دستی به محصول یا کارخانه‌ی demo اضافه کرده‌اید (قیمت، مکاتبه، …) پاک می‌شود. داده‌ی واقعی را روی محصولات و کارخانه‌های واقعی ثبت کنید.
- اگر `auth.enforce_permissions` روشن است، دسترسی‌های تازه را در «نقش‌ها و دسترسی» به نقش کارشناس بدهید.
